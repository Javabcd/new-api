# New-API 通用视频生成游乐场：Codex 实施计划（复核修订版）

版本：v2  
复核日期：2026-10-13  
目标仓库：`Javabcd/new-api`  
范围：新增一个「视频生成」菜单，使四个现有视频插件在同一页面可调用。

> 本计划依据本次可读取的公开 `main` 源码进行静态复核，不代表已经验证用户部署版本、运行中插件、渠道、价格配置或真实上游。
> Codex 开始时必须记录本地分支、HEAD、未提交改动及运行中插件版本；以实际工作树为准核对差异。不得将本计划的模型示例当作线上配置。
> 本计划替代上一版，而不是与上一版冲突条款同时执行。

## 1. 目标与实施边界

实现独立的视频游乐场，不把视频任务伪装为 Chat Completions。

必须覆盖：

| 插件 | 当前源码中的 key | 首轮文生视频测试模型示例 |
|---|---|---|
| 原有 Doubao Seedance | `doubao` | `doubao-seedance-2-0-260128` |
| Millu Seedance | `millu-seedance` | `millu-sd-x-2-5-260801` |
| CTYun Cdance | `ctyun-cdance` | `cdance2.0-0807` |
| China Mobile MoMa Seedance | `moma-seedance` | `doubao-seedance-2-0-260128` 或插件声明的 MoMa 别名 |

四个插件必须全部完成适配及自动化测试，不得只交付 Millu。各模型只开放实际支持的生成方式，不能推定同一插件的所有型号都支持文生视频和图生视频。

P0 交付：菜单、模型/供应商选择、文生视频、支持型号的 URL 图像参考、参数校验、提交、任务恢复与查询、播放、下载、鉴权、既有计费、必要的幂等安全。

P1 扩展：本地上传及素材存储、更多参考视频/音频和首尾帧操作、费用预览、批量操作。只为已经确认支持的模型启用。不得因 P1 未实现而掩盖四个插件的 P0 缺项。

不在本次范围：重写任务系统、替换计费引擎、改造全部公共 API、引入新的通用表单 DSL/完整插件能力框架、批量视频生成、未经授权的真实扣费测试。

## 3. 已核实的关键事实与限制

以下为本次源码检查结果，实施时仍须核对当前分支：

| 对象 | 应遵循的事实 |
|---|---|
| 四个插件 | 均声明 `openai_video`，但这只表示协议入口支持，并不等于参数、模式、上传能力完全相同。 |
| `doubao` | `meta.models` 同时包含图片与视频模型；应读取 `openai_video` 对应的模型子集，不能展示 Seedream 图片模型。保留其 legacy `channelTypes` 兼容。 |
| `millu-seedance` | 当前已声明型号支持的分辨率为 720p、1080p；插件拒绝智能时长 `-1`、`frames` 及非空自定义 `callback_url`。多图需要明确 role，尾帧须配首帧；首尾帧场景对 ratio 有额外限制。 |
| `ctyun-cdance` | 当前提交校验要求明确提供 duration/seconds 以及 resolution/size，各型号的分辨率集合不同。当前没有声明 `upstreams: ["new_api"]`，不能把 type-60 级联支持当作本次验收前提。 |
| `moma-seedance` | 接受两个已声明模型名并映射到其上游模型；禁止 resolution、size、frames。时长可省略，提供时当前插件限制为 4–15 秒；ratio 为 16:9、9:16、1:1。参考媒体使用 HTTP(S) URL，只允许相应的普通 reference role。 |
| 宿主安全上限 | Millu、CTYun 中的 3600 秒是宿主输入安全限制，不能宣称模型真实支持生成一小时视频。真实能力不明的范围不得包装成已验证能力。 |
| 媒体上传 | 当前四个 OpenAI Video 解码器都拒绝真正的 multipart 文件部分；可解析 multipart 文本字段不等于支持本地文件上传。P0 使用媒体 URL。 |
| 视频结果 | 已存在控制台产物接口及宿主内容代理，应复用，不另建一套视频下载链路。 |

能力信息优先来自运行中的已加载插件及已验证的适配配置，而不是插件市场索引、文件名或模型名的字符串猜测。

`usageSchema` / `usageProfiles` 是计费事实描述，不是完整的生成表单 schema。不得把计费用的字段枚举直接当作全部上游参数能力。

## 4. 前端菜单与用户体验

新增一个「视频生成」菜单，建议路由 `/video-playground`，最终遵循实际路由与导航规范。

检查并同步处理：侧边栏、移动端导航、菜单显示设置、用户导航偏好、权限控制、国际化、直接访问 URL 的登录跳转。不得仅修改侧边栏就认定完成。

复用 React、TanStack Router/Query、现有表单、API 客户端、任务列表、错误展示、复制和媒体预览组件，不引入第二套 UI 框架。

页面以「插件/供应商 + 对外模型名」标识选项；当前分组参与可用性及缓存键。同名模型必须明确展示其供应商，不能在下拉框中合并。

模型切换时，删除前一模型不支持的字段及媒体角色，特别防止把 Millu 的 resolution 或首尾帧角色带到 MoMa。

布尔选项支持“未设置 / true / false”的语义；必要时使用“使用上游默认值”选项。不要把未填写变成 0、空字符串、false 或固定默认值。

提交前给出会产生费用的提示。单次提交 pending 时禁止双击；提交结果未知时不提供会无条件新建任务的“自动重试”。

模型列表空、渠道不可用、参数不兼容、价格未配置、余额不足、提交结果未知、任务失败、产物已过期，应分别呈现，不统一显示为 distributor 错误。

## 5. 模型发现和能力接口

建议新增 `GET /pg/video/models`，按当前用户及服务端校验通过的有效分组返回模型选项。具体路由可按仓库规范调整。

数据来源与判定包括：

1. 当前运行中且可用的插件、`openai_video` 模型声明。
2. 当前有效的渠道状态、插件绑定、模型能力和分组。
3. 现有用户权限与模型权限；不能把管理员渠道管理接口直接开放给普通用户。
4. 已有别名/模型映射解析，以及插件级有效定价状态。
5. 本次最小化的视频参数适配配置。

不得只取 `meta.models`，不得只检查 `abilities` 中存在该模型就宣称可调用。必须复用当前渠道匹配语义，包括 Task Plugin 身份和受支持的 legacy 渠道。

别名需要保留对外模型名；上游映射名只用于校验/执行，不能代替对外显示及计费身份。无法消除歧义的映射标记为不可用，不推测供应商。

多个同插件、同模型渠道仍使用现有优先级/权重。若不同映射目标具有不同能力，不能显示所有能力的并集后随机分配；应采用安全交集或既有的请求兼容过滤，并覆盖测试。

能力返回可包含：plugin_key、model、display_name、supported_modes、可选参数/必填参数、媒体类型/角色、已确认限制、availability、disabled_reason。不返回上游密钥、完整渠道配置或管理字段。

该接口为无副作用读取：不得提交上游任务、预扣费、改变渠道亲和性或触发自动禁用。提交时必须重新校验可用性，不信任之前的列表快照。

## 6. 后端调用链和严格插件身份

### 6.1 独立的视频提交路由

建议新增：

- `GET /pg/video/models`
- `POST /pg/video/tasks`
- 如单任务查询确有需要：`GET /pg/video/tasks/:task_id`

优先复用现有：

- `GET /api/task/self`：当前用户任务列表，可复用当前支持的任务 ID / 状态 / 平台等筛选。
- `GET /api/task/:task_id/artifacts`：控制台产物清单。
- 产物清单返回的 `content_url`：视频播放和下载。

这些新路由是拟新增设计，不是现有 API。

当前聊天 `/pg` 路由组已经挂载 `UserAuth(), Distribute()`。视频的插件身份准备必须发生在 `Distribute()` 之前，因此不得简单将视频处理器追加到现有父组、再在处理器中才设置 pluginKey。

模型列表和任务读取不应进入模型渠道分配及预扣费。

### 6.2 复用的是宿主执行链，不是转发一个 HTTP 请求

建议调用关系：

浏览器登录态请求
→ 会话与权限校验、用户/额度上下文
→ 解析并校验有效分组、模型、pluginKey、生成参数
→ 固定本次使用的插件 generation 与唯一插件
→ 生成插件实际接受的请求、完成解码/校验
→ 限流与现有渠道分配
→ 现有任务提交编排、预扣费、落库
→ 现有后台轮询、结算和产物访问

选择最小可行的内部复用方式：限定插件的协议准备，或限定插件的通用任务准备；明确选择一种主路径，不同时实现多条互相兜底的提交分支。

当前 `PinTaskPluginEndpoint()` 会依据请求 method/path 查找协议，因此新建 `/pg/video/tasks` 后，不能假设原有 `/v1/videos` 中间件会自动识别它。应提供明确的内部协议/插件准备入口，避免靠临时改写 URL 让路由“碰巧工作”。

通用 `/v1/tasks/{pluginKey}` 的准备逻辑并不等价于执行插件 `openai_video.decodeRequest`。复用通用入口时必须补足经过确认的请求格式转换、校验与 action，不能省略这些步骤。

禁止：浏览器直连供应商、让用户填写上游 Key、服务端向自己发 HTTP 请求绕过上下文、删除 Task Plugin 身份过滤、用管理员权限代替用户权限、另写预扣费和任务落库流程。

### 6.3 同名模型与候选插件集合

`doubao` 与 `moma-seedance` 均可能提供 `doubao-seedance-2-0-260128`。

不变量是：实际执行插件必须等于用户选择的插件。首次选路、故障重试、渠道亲和性、type-60 多插件绑定、模型映射和价格解析都必须遵守。

不能只设置 `expected_task_plugin_key`，却保留公共 `/v1/videos` 中其他供应商的候选插件。当前候选集合参与渠道匹配，必须在进入分配前将本次候选范围收窄到所选插件，或使用已经验证只固定一个插件的入口。

未选供应商的渠道即使优先级更高也不能被调用。所选插件没有渠道时明确失败，不能静默跨供应商 fallback。

仅对实际声明 `new_api` 能力的插件测试 type-60 级联；CTYun 当前未声明，不在此功能中顺手扩展。

## 7. 统一表单 DTO 与插件请求转换

以下为拟定的游乐场 DTO，不是上游请求，字段命名可随项目规范统一：

```json
{
  "plugin_key": "ctyun-cdance",
  "model": "cdance2.0-0807",
  "group": "default",
  "prompt": "一只小猫在草地上奔跑",
  "media": [],
  "parameters": {
    "duration": 5,
    "resolution": "720p",
    "ratio": "16:9",
    "generate_audio": false
  }
}
```

`media` 单项可使用内部 `{type, url, role}` 结构。提示词只有一个权威输入源，不同时允许顶层 prompt 和 content 中另一份文本默默覆盖。

对目前四个插件，可优先验证如下内部请求形状：

```json
{
  "model": "cdance2.0-0807",
  "prompt": "一只小猫在草地上奔跑",
  "seconds": 5,
  "metadata": {
    "content": [],
    "resolution": "720p",
    "ratio": "16:9",
    "generate_audio": false
  }
}
```

该例只说明字段放置位置；实际字段必须经过对应插件能力校验。不要直接把该例套给 MoMa。

关键转换要求：

- Doubao：prompt 保留在顶层；时长使用驱动实际读取的 seconds；分辨率、ratio、音频和媒体内容放到对应 metadata 字段。其构建请求过程会重建文本 content，因此不能只把文本放在 metadata.content 中而丢掉 prompt。
- CTYun：媒体 content 放在 metadata.content；顶层随意附加 content 不能保证被其驱动读取。duration/seconds、resolution 必须满足当前插件校验。
- Millu：保留素材 role，不重复插入 prompt；禁止当前插件不支持的字段及组合。
- MoMa：完全不传 resolution、size、frames，时长省略时仍省略；只允许其参考角色及参数。
- 对每个插件保存“UI DTO → 内部插件请求 → 最终上游 JSON”的测试样例，断言实际请求字段，而不只是 HTTP 返回 200。
- UI 字段必须逐项映射；禁止无约束的 options/metadata 透传。不能让客户端覆盖 model、upstreamModel、baseUrl、认证头、计费事实或渠道身份。
- 不支持的输入在服务端明确拒绝，不能默默忽略并照常收费。
- 可选数字/布尔请求字段在 Go 中保留 presence 信息，遵守项目 pointer + omitempty 规范；显式 false 不能被丢弃。
- 自动填入的 UI 预设必须可见且由用户确认；预估用默认值绝不能写入真实上游请求。
- 媒体模式和 task action 从已校验的输入及插件能力得出，不能信任客户端自报 mode/action。

## 8. 登录态、分组与授权

复用当前 Dashboard 登录态和前端统一 API 客户端，不自创 cookie、JWT 或长效 API Key 方案。

当前 `UserAuth` 支持多种 Dashboard 凭据；视频游乐场按真实会话接口处理，参照现有会话专用路由规则，明确拒绝不在支持范围内的 PAT/legacy access token，不仅依赖前端隐藏入口。

参考 `controller/playground.go` 的用户缓存和临时 Token 上下文建立方式，但必须验证异步任务能安全使用，不可复制零散 `c.Set` 字段后假定计费完整。

临时 Token 如用于上下文，应保持内存使用，不创建/泄露真实长期令牌。检查后台结算对 token_id=0、钱包、订阅、用户状态及额度的既有行为。

分组只能取当前用户被允许使用的值；不允许前端 group 覆盖权限，不擅自把 auto 替换成 default。不同分组报价、选路与缓存必须一致。

创建前完整执行模型权限、有效分组、频率限制和额度检查。查询、产物清单签发只访问本人任务，管理员权限沿用现有规则。

不能因当前模型或渠道被禁用，就在前端删除用户历史记录；读取已有任务不重新选择供应商。无法获取历史产物时提示实际原因。

用户切换、退出登录时清理相关 Query 缓存；所有用户数据查询的缓存键必须包含身份及必要的分组上下文。

## 9. 提交幂等与不确定结果

禁用按钮仅防一次页面内双击，不是服务端幂等。

同一次提交意图生成固定 `Idempotency-Key`。网络重试、认证刷新后的重放使用同一个 key；用户明确发起新的生成才换 key。

检查宿主是否已有可复用的幂等机制。要求在多实例环境下同一个用户及 key 的并发请求不会重复预扣或创建两个上游任务；以规范化请求指纹核对 pluginKey、model、有效分组、prompt、媒体和参数。同 key 不同请求返回冲突。

优先复用当前任务存储和执行编排；确有缺口时允许最小幂等记录/索引，但不要另建完整的视频业务任务系统。新增数据库行为按第 13 节验证。

Millu 插件可以发送幂等请求头，但这不自动等于宿主已经实现幂等。尤其不要在重试时切换上游账号/密钥/渠道后还声称同一个供应商幂等键能去重。

对没有已验证创建幂等能力的供应商：请求已可能送达后的超时属于结果不确定，不得自动再次 POST、跨渠道重试或把它当成明确失败。先通过已有记录/任务 ID 恢复；没有可恢复信息时明确显示待核实状态。

需单独检查并测试：
- 请求发送前失败。
- 上游已接受但响应未回到浏览器。
- 上游返回任务 ID 后本地落库失败。
- 本地任务已落库但浏览器断线。
- 登录凭据刷新造成原始 POST 重放。
- 双标签页及双实例的同 key 并发。
- 幂等记录未完成或进程重启后的恢复。

Millu 的用户提供文档提示创建请求可能等待很久，并建议客户端等待窗口至少 910 秒。该提示需要在接入环境中核验，不直接改成全站超时。检查浏览器 HTTP 客户端、反向代理、服务端及插件请求的各层 timeout，只给必要链路设置经过确认的边界。

优先复用既有受控执行/持久化能力；不得用无上限 `context.Background()` 或只存在进程内的 goroutine 假装任务已可靠接收。未完成持久化前不能宣称可以刷新页面恢复。

## 10. 任务查询、历史与状态

提交成功只向浏览器返回 New-API 的公开 Task ID，不暴露供应商 task ID 或上游密钥。

页面刷新、重新进入页面后，通过服务端记录恢复未结束任务，不能只依赖 localStorage。前端本地状态只能作为表单草稿或查询线索，不能作为账单事实。

优先复用 `/api/task/self`；若筛选不够，最小扩展用户级查询。Doubao 同时有图片任务，不能仅按 platform=doubao 就把全部历史当成视频。

后台轮询负责查询上游并结算；浏览器主要查询宿主已持久化状态。不要每个浏览器标签页再起一套直接上游轮询。

宿主 `SUCCESS`、`FAILURE` 等为终态判定依据；上游 queued/running/succeeded/cancelled/expired 可作安全的显示补充。若现有记录没有保留可区分的上游终态，不臆造“已取消”或“已过期”。

终态停止前端轮询；非终态采用适当间隔/退避和页面隐藏降频。请求暂时失败不等于生成失败，不修改账单、不自动退款。

显示阶段状态，不编造真实百分比。若复用插件给出的阶段性进度，应明确是阶段进度而非真实生成完成比例。

查询返回最小化 DTO，不把完整 task.data、PrivateData、渠道信息或认证相关字段返给普通用户。

未实现取消 API 的插件不显示可用的取消按钮。停止浏览器轮询不等于取消上游任务。

## 11. 视频播放、下载及链接安全语义

复用 `GET /api/task/:task_id/artifacts` 获取宿主签发的 `content_url`。播放器按产物 type/mime_type 使用，不假定响应必有顶层 video_url，也不假定所有结果都能以 MP4 播放。

不把需要手工 Bearer 头的普通 API 地址直接当作无鉴权 src，不把用户完整 API Key 或登录凭据放入 URL。

当前 `service/task_artifact_access.go` 生成的是长期、绑定 task ID 和 artifact key 的持有者授权链接，不是自动带短有效期的 URL。
因此明确区分：
- 未经授权的用户不能枚举他人任务、读取清单或获取他人的产物链接。
- 拿到合法产物链接者可按现有分享语义访问。不能声称它“必须本人登录才可播放”或“退出登录即失效”。

本次保持既有访问语义，不悄悄改全局签名协议；不额外开发复制分享链接按钮。产物访问凭据避免出现在应用日志、分析埋点和外部 Referer 中。

核对 `TaskPublicAddress` / `ServerAddress`、HTTPS 及实际可访问性，不从任意请求 Host 构造公开地址。

复用既有媒体代理、内容存储、Range/HEAD 和防 SSRF 机制，不把大视频完整读入内存或浏览器 Blob 后才开始播放。验证实际浏览器播放、拖动和下载，而非只测 JSON 成功。

宿主授权链接和上游视频 URL 的有效期是两回事。重新签发宿主链接不能自动延长上游 URL。已有宿主缓存/存储可用时复用；没有保存且上游已失效则如实提示，不自动重新生成或承诺永久保存。

P0 输入为用户提供的媒体 URL，不新增服务端任意 URL 下载器。以后实现本地上传时，需要单独验证存储、访问范围、素材生命周期、大小与类型、恶意文件及上游可访问性。

## 12. 计费约束

全部复用既有任务链路：校验、用量预估、价格解析、额度预留、任务落库、完成结算、失败处理及日志。

确保所选插件、实际执行插件、价格解析插件、任务保存插件一致。复用当前插件级表达式覆盖与别名解析，不新写一套 `<pluginKey>::<model>` 查询优先级。

预估费用、实际用量和最终费用分开。上游缺失 usage 时沿用宿主现有策略，不能把估算值标为“上游实测”。

不得因前端切换页面、取消请求或轮询报错触发退款。已经持久化的任务只由既有结算机制完成一次结算；失败退款同样不得重复。

对 nil/false/0、异常超大时长、resolution 组合、未知 metadata 和重复字段执行必要的服务端校验，防止绕过计费数量边界。

P0 不强制增加费用预览；没有可靠复用入口时先完成正确收费，不硬编码供应商价格或推测账户费用。

## 13. 自动化测试及真实验证

优先扩展已有合适的测试文件，采用可观察结果的表驱动测试，不为同一小功能在多层重复堆测试文件。

至少覆盖：

| 范畴 | 核心验收 |
|---|---|
| 四插件端到端模拟 | 通过真实路由/中间件/宿主提交编排，接本地模拟上游；四者分别提交、持久化、查询、成功产物和失败流程。不能仅 Mock 页面 API 后宣称适配完成。 |
| 上游请求契约 | 捕获最终上游 JSON：Doubao prompt/seconds/metadata，CTYun metadata.content 与必填参数，Millu role/ratio 组合，MoMa 无 resolution/size/frames。 |
| 值语义 | 显式 false 保留；未填 duration/参数不被改写；冲突 duration/seconds、超大值、未知字段被拒绝。 |
| 同名模型 | 另一个供应商优先级更高仍不串线；所选供应商无渠道时不 fallback；同插件重试保持正确身份。 |
| 渠道与模型 | legacy/type-61、声明支持时的 type-60；CTYun 未声明的级联不被误放行；模型别名、同名模型、分组、禁用插件和禁用渠道。 |
| 中间件顺序 | 视频身份准备发生在分配之前；GET 模型/任务无 model 请求体也能工作且不执行生成/预扣。 |
| 登录与隔离 | 未登录、禁用用户、过期会话、不支持的 PAT、越权 group、他人 task ID/产物清单、前端切换账户缓存。 |
| 幂等与故障 | 双击、双标签、双实例、认证刷新重放、上游响应丢失、落库前后断线、同 key 不同请求；不会盲目重发或重复收费。 |
| 轮询与终态 | 队列、运行、成功、失败、可区分时的取消/过期、临时查询失败、刷新恢复；不覆盖宿主终态、不重复结算。 |
| 产物 | 合法链接播放/下载、篡改 task/artifact/access 被拒绝、未授权获取清单失败；合法分享链接按现有授权语义工作。 |
| 浏览器 | 实际菜单访问、模型切换去掉残留字段、参考图传入上游、视频播放/拖动、过期结果提示、移动端及语言切换。 |
| 无回归 | 原 Chat Playground、既有 `/v1/videos`、通用任务 API、native routes 和现有任务日志仍可工作。 |

使用可控的模拟时钟、HTTP 响应和故障注入测试超时；不要通过真实等待 910 秒或长时间 sleep 测边界。

运行当前项目存在的检查：
- 相关 Go 测试，以及仓库要求的 `make test`/构建。
- `web/` 下适用的 `bun run typecheck`、`bun run lint`、`bun run test`、`bun run build`。
- 触及独立模块时执行其要求的独立构建。

数据库验证不只限于新增表。新增/修改查询、事务、索引、锁、序列化、幂等持久化等数据库行为，都要按 AGENTS.md 在真实 SQLite、MySQL、PostgreSQL 上验证。发生 schema/migration 变更时覆盖全新库和旧版升级，重复启动验证幂等。

真实供应商调用需要明确授权、有效测试凭据及费用上限；“找到了密钥”不等于获得扣费许可。没有授权时只执行模拟测试并给出人工验收步骤，不修改生产数据。

## 14. 实施顺序与交付判定

阶段 A：确认当前代码、最小路由方案、唯一插件约束和四插件请求样例。  
阶段 B：先完成后端会话提交链与四插件契约测试，再实现/接入前端。  
阶段 C：模型发现、动态表单、已有任务记录和产物播放。  
阶段 D：幂等、故障恢复、安全、计费及旧 API 回归。  
阶段 E：按授权情况完成真实环境验收。

可并行处理前端和插件测试，但路由、DTO、插件身份及计费边界由同一集成负责人统一确认。不要让多个代理分别改出四套不一致提交接口。

完成后报告：

1. 实际本地 HEAD、涉及文件、新菜单路由及接口。
2. 四插件支持矩阵：模型、生成方式、参数、已验证与未验证项。
3. 哪些现有组件/服务被复用；必要新增逻辑及原因。
4. 同名模型、幂等、登录态、任务恢复和计费验证结果。
5. 实际执行的命令、结果及数据库版本；区分新增失败与基线失败。
6. 尚缺环境、凭据、真实浏览器或供应商验证的具体事项。

完成标准分层报告，不混为一谈：
- 代码实现完成。
- 自动化及构建验证通过。
- 真实供应商闭环验证通过。

四个插件任何一个只实现了模型下拉选项、没有实际请求契约测试，不算“已兼容”。Mock 成功不算真实供应商调用成功。存在必要的数据库或安全验证缺口时，不声称生产可用。
